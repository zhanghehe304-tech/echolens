# echolens

语音识别的**端到端小流水线**：源-滤波器合成多说话人语音 → log-mel 特征 → 小型 CTC 模型 → 三档解码（贪心 / beam search / beam + 音素 bigram）→ 音素错误率（PER）、词错误率（WER）、跨说话人泛化、噪声鲁棒性（含训练时加噪的对照）→ 逐样本对齐 → 单文件 HTML 报告。

一条命令，纯 CPU，约两分钟跑完，出来一个可以贴进周报的网页报告。

![report preview](https://aka.doubaocdn.com/s/edB2MOeDWB)

> 上图是 `echolens demo --noise-aug-random 0,20 --noise-aug-copies 3` 那份报告的截图：1200 句随机加噪训练、60 轮、训练 8.6 分钟，多出来的 `Noise augmentation` 区块是"干净训练 vs 加噪训练"的噪声曲线并排对照。

## 快速开始

```bash
pip install -e .
echolens demo                             # 默认：干净训练，约 2 分钟
echolens demo --noise-aug 20,10,0         # 训练集加噪（固定三档），先训一个干净基线做对照，约 10 分钟
echolens demo --noise-aug-random 0,20     # 训练集随机加噪（每句在 0–20 dB 采一档，×3），约 11 分钟
```

跑完后：

- `out/data/` — 360 个 16-bit WAV 和 `train.jsonl` / `dev.jsonl` / `dev-unseen.jsonl`
- `out/echolens.pt` — checkpoint
- `out/echolens-report.html` — 报告（图片 base64 内联，单文件，直接双击打开）

默认参数：300 句训练 / 40 句开发 / 20 句"没见过的音色" / 60 轮 / 训练集 4 个说话人 / 采样率 8 kHz。

## 实测结果

默认参数（**训练不加噪**），CPU 上整跑约 **2 分钟**，报告内 elapsed 1.8 分钟（纯训练）：

| 指标 | 训练里见过的音色 | 没见过的音色 (s5–s8) |
| --- | --- | --- |
| dev 音素错误率 PER | **0.018** | 0.062 |
| dev 词错误率 WER | **0.073** | 0.214 |
| dev 整句全对率 exact match | **0.900** | 0.700 |

跨说话人泛化是这一版最想量准的东西：训练只喂 s1–s4，`dev-unseen.jsonl` 里全是 s5–s8，两个集合没有交集，单测里断言了这个不相交。

## 换合成器把泛化差距从 10 倍压到 3 倍

v0.3.0 的合成器是"每个音素一个正弦 + 二三次谐波"，音色差别全落在谐波权重上。那里量出来的跨说话人代价是这样的：见过的音色 PER 0.036，没见过的 0.366——**十倍**。这个数不好解释：它到底是模型学不到音素共有的声学线索，还是合成器把"音色"做成了和音素内容纠缠的东西，没人说得清。

v0.4.0 把合成器换成源-滤波器模型：声门脉冲串（浊音）或带通噪声（擦音、爆破）作声源，过三级共振峰滤波器，再过一次差分模拟唇端辐射。音素身份由 F1/F2/F3 决定，说话人身份由声道长度（共振峰整体缩放）、基频、声门谱倾斜决定。

同一套训练配置、同一批说话人划分，未见音色的 PER 从 0.366 落到 **0.062**，在域内也从 0.036 落到 0.018。这说明 v0.3.0 里那 10 倍的差距主要不是模型的问题，而是合成器把音色和音素内容绑在了一起：正弦频率本身就是"音素"，换个说话人相当于换了一套音素，模型当然认不出来。

## 音高增强：曾经有用，现在没用了

| 训练集音高抖动 | 见过音色 PER / WER / exact | 没见过音色 PER / WER / exact |
| --- | --- | --- |
| 0.00（现默认） | 0.018 / 0.073 / 0.900 | 0.062 / 0.214 / 0.700 |
| 0.06（v0.3.0 默认） | 0.014 / 0.055 / 0.925 | 0.062 / 0.179 / 0.750 |
| 0.12 | 0.009 / 0.036 / 0.950 | 0.071 / 0.214 / 0.700 |

v0.3.0 里这个旋钮很值钱：不加增强时未见音色 0.634，加到 0.06 后降到 0.366。换到共振峰合成之后它就不值钱了——三档的未见音色是 0.062 / 0.062 / 0.071，差别在 1–2 个音素的量级（40 句开发集、约 240 个音素，一个音素就是 0.004），不足以判定哪档更好；而它也不再承担"跨音色泛化"这个角色。

原因很直接：以前音色就是音高，抖基频等于扩了音色分布；现在音素身份在共振峰上，抖基频只是把声源换个高度，模型要学的"音素长什么样"根本没被扰动。所以默认改成 0，`--f0-jitter` 保留下来做实验，不再当推荐配置卖。

## 噪声鲁棒性

同一个 checkpoint，在开发集波形上按标称 SNR 混白噪后重新提特征：

| 条件 | PER | WER | exact |
| --- | --- | --- | --- |
| 干净 | 0.018 | 0.073 | 0.900 |
| 20 dB | 0.091 | 0.309 | 0.600 |
| 10 dB | 0.123 | 0.400 | 0.575 |
| 0 dB | 0.305 | 0.745 | 0.250 |
| −5 dB | 0.582 | 0.964 | 0.025 |

两个要说明的地方。第一，SNR 按**全带**功率定义（噪声铺满 0~4 kHz），落进语音主频带的那部分比标称值低，所以这组数是相对刻度，不是声学实验室的 A 加权信噪比。第二，20 dB 就掉到 0.091 看着有点狠：CMVN 会把整体电平拉回来，所以这里掉的不是音量，是噪声纹理——训练数据是干净的，模型没学过"有噪声的共振峰"长什么样。

## 训练时加噪：抗噪是花钱买的，代价出在陌生音色上

`--noise-aug 20,10,0` 会先把训练集按这三档 SNR 各复制一份并混白噪（300 句 → 1200 句），标签不动，然后**用同一套配置先训一个干净基线**，两张噪声曲线并排进报告。为了让"数据量变大"这半边也被量到，我又单独跑了一个对照组：干净数据复制 4 份，共 1200 句，不加噪。第四行是 `--noise-aug-random 0,20 --noise-aug-copies 3`：每句各自在 0–20 dB 里采一档信噪比，同样 1200 句。

| 训练配置 | 训练量 | 干净 PER / WER / exact | 20 dB | 10 dB | 0 dB | −5 dB | 未见音色 PER / WER |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 干净，默认 | 300 | 0.018 / 0.073 / 0.900 | 0.091 | 0.123 | 0.305 | 0.582 | 0.062 / 0.214 |
| 干净复制 4 份（对照） | 1200 | 0.005 / 0.018 / 0.975 | 0.068 | 0.068 | 0.218 | 0.550 | 0.027 / 0.107 |
| 加噪 20/10/0 dB（固定档） | 1200 | 0.000 / 0.000 / 1.000 | 0.000 | 0.000 | 0.027 | 0.259 | 0.045 / 0.179 |
| 加噪 0–20 dB（随机档，×3） | 1200 | 0.000 / 0.000 / 1.000 | 0.000 | 0.005 | 0.045 | 0.309 | 0.027 / 0.107 |

（噪声列都是 PER，解码固定 beam、宽度 10。）

读这张表要分四层：

1. **训练量本身就有用，但没那么有用。** 光把 300 句复制成 1200 句，−5 dB 从 0.582 到 0.550，0 dB 从 0.305 到 0.218，域内从 0.018 到 0.005。这解释了"加噪模型域内 0.000"的一部分——其中有一半是"训得更久"，不是噪声的功劳。
2. **抗噪还是噪声买下来的。** 同样是 1200 句，0 dB 从 0.218 掉到 0.027、−5 dB 从 0.550 掉到 0.259，20 dB 和 10 dB 直接清零。对照组这两档数字完全相同（0.068/0.273/0.650），我单独重跑确认过——说明干净模型在这些信噪比下错的是同一批句子，错误由"某个音素在噪声纹理下辨不出"这种结构性原因支配，而不是随 SNR 平滑退化。
3. **代价出在陌生音色上。** 固定档的未见音色是 0.045 / 0.179，比对照组的 0.027 / 0.107 更差（仍好于 300 句基线的 0.062 / 0.214）。模型把容量分给了"噪声下的共振峰"，能分给"没听过的声道长度"的就少了。这是真实的取舍，不是可以顺手抹平的东西。
4. **随机档把这笔代价还了回去，但极端档位让了一点。** 未见音色回到 0.027 / 0.107，和"只加数据量"的对照组一模一样；0 dB 是 0.045 而不是 0.027，−5 dB 是 0.309 而不是 0.259，10 dB 还漏了 0.005。差别的原因很直白：固定档训练的信噪比正好是评测的那几档，相当于对着考卷复习；随机档每句的信噪比都不同，模型学到的是"一整个区间的噪声"，所以跨区间和跨音色都更稳。要极致压低某个已知档位，用固定档；要一个不挑档位的模型，用随机档。

另外两点得说清：0.000 和 0.005 都在"对错一两个音素"的量级——40 句开发集约 240 个音素，一个音素就是 0.004，别把它读成算法奇迹；加噪训练也贵，60 轮从 1.8 分钟涨到 7.9 分钟（固定档）/ 8.6 分钟（随机档，含先训的干净基线）。

所以默认**不开**：默认 demo 保持 2 分钟、并保住陌生音色。要抗噪就显式给档位——已知档位用 `--noise-aug 20,10,0`，要一个通用的抗噪模型用 `--noise-aug-random 0,20`，报告里都会自动多出那张对照表。

## 解码：三种方式，收益并不均匀

| 解码 | 见过音色 PER / WER / exact | 没见过音色 PER / WER |
| --- | --- | --- |
| greedy | 0.018 / 0.073 / 0.900 | — |
| beam (宽度 10) | 0.018 / 0.073 / 0.900 | 0.062 / 0.214 |
| beam + 音素 bigram（权重 0.3） | 0.018 / 0.073 / 0.900 | **0.054** / **0.179** |

三件事值得说清：

1. **beam 这一版仍然没有收益。** 在域内 PER 只剩 0.018，模型每一帧都足够笃定，beam 和 argmax 完全重合。beam 本来就只在模型犹豫时才有用，这是它的定义，不是实现退化。
2. **音素 bigram 在熟悉音色上一点用都没有**（0.018 → 0.018），因为已经没有音素级接续错误可纠；在陌生音色上它同时改善 PER（0.062→0.054）和 WER（0.214→0.179）——和 v0.3.0 正好相反，那一版它是"拿音素指标换词级指标"。
3. 同一个 LM 在不同模型质量下干的是不同的活：模型越好，LM 越只是"锦上添花的先验"；模型越差，它越是在拿一个指标换另一个指标。所以报表必须把两档并排列出来，否则单看一个数就会误读。

`--lm-weight 0.3` 是手定的，没有在开发集上搜索过（在开发集上搜就等于偷看测试集）；换数据要自己重调。

## 它到底在做什么

1. **合成语料**（`echolens/tables.py`、`dsp.py`、`synth.py`、`corpus.py`）。10 个音素：五个元音（F1/F2/F3 分别是 760/1180/2600 这类设计值）、鼻音 `m`（低位极强、增益压低）、流音 `r`、擦音 `s`（3.4 kHz 窄带噪声）、爆破音 `k` `t`（前段闭合 + 衰减的噪声爆破）。声源是声门脉冲串（周期由 f0 决定，脉冲宽度由声门倾斜决定）或白噪声，声道是三级两极点共振峰级联，最后过一阶差分模拟唇端辐射。16 个 3–5 音素词，每句随机 1–2 个词。八个说话人各有稳定的参数（基频倍数 0.80–1.62、声道长度倍数 0.88–1.14、语速、声门倾斜、底噪）；训练集用前四个，后四个留给泛化测试。
2. **特征**（`echolens/audio.py`）。纯手写：WAV 读写、线性插值重采样、numpy 三角 mel 滤波器组，输出 40 维 log-mel（25 ms 窗 / 10 ms 帧移 / n_fft 256），逐句 CMVN；`add_noise()` 按目标 SNR 混白噪，评测和可选的数据增强都用它。
3. **模型**（`echolens/model.py`）。`Conv1d(40→64)` → `Conv1d(64→64)` → BiGRU(96) → Linear(192→11)，CTC blank=0，总计约 25 万参数。
4. **训练**（`echolens/train.py`）。Adam + 余弦退火 + weight_decay + 梯度裁剪，`CTCLoss(zero_infinity=True)`，每轮报 dev PER；`--noise-aug` 只是把训练集按档位复制一份带噪版本，训练代码本身不动。
5. **测评**（`echolens/metrics.py`）。三档解码共用同一套编辑距离回溯（match / sub / del / ins）；PER 按参考音素总数加权，WER 按参考词边界切分对齐结果。beam 能出 nbest，`PhoneLM` 用它做 rescoring。
6. **报告**（`echolens/report.py`）。指标卡、Training 曲线、Decoder comparison、Speaker generalisation、Noise robustness、Noise augmentation（干净训练 vs 加噪训练并排）、逐样本表（`reference` / `hypothesis` / `diff` / `words` / `err`）。

## 两个值得记下来的细节

**一、按符号判"冲激响应到头了"，会把滤波器切成 1 ms。** 共振峰的闭式冲激响应是 `r^n sin((n+1)ω)/sin(ω)`，我在截尾时写成了"第一个幅值小于阈值的位置"：`np.argmax(h < 1e-3 * h.max())`。正弦一旦变负，这个比较立即为真，于是 198 个采样的滤波器被截成 8 个采样，共振峰全部失真成"短促的响一下"。表现是模型在 40 轮里几乎学不动（PER 0.977）。改成按包络 `r^n` 判尾长（`log(1e-3)/log(r)`）之后，冲激响应的频响峰值稳稳落回设计频率（760 Hz 测得 759 Hz）。**判"衰减到头"要用绝对值或包络，不能用带符号的样本值。**

**二、声道的"缩放"方向很容易弄反。** `VOICES` 里的 `vtl` 我第一版当成"共振峰倍率"直接乘上去了——声道越长、共振峰越高，物理上正好反着。症状是"男声比女声还尖"。单测里加了一条"声道更长的人 F1 更低"（s6 vtl=1.14 vs s4 vtl=0.88），它比任何指标都更早抓到这种方向错误；现在 `vtl` 是声道长度倍数，共振峰按 `1/vtl` 缩放，命名和物理含义对上了。

## 解码方式、增强与噪声

```bash
echolens demo --decode greedy              # 主结果换成贪心
echolens demo --decode beam+lm             # 加音素 bigram rescoring
echolens demo --beam-size 20 --lm-weight 0.5
echolens demo --f0-jitter 0.12             # 打开音高增强（默认 0）
echolens demo --speakers 2 --dev-unseen 0  # 只训两个音色、不测泛化
echolens demo --snr 10,0                   # 只扫这两档噪声
echolens demo --noise-aug 20,10,0          # 训练时加噪（固定三档），并自动训一个干净基线做对照
echolens demo --noise-aug-random 0,20      # 训练时随机加噪：每句各自在 0–20 dB 里采一档
echolens eval --manifest out/data/dev-unseen.jsonl --checkpoint out/echolens.pt --decode beam+lm
echolens eval --manifest out/data/dev.jsonl --checkpoint out/echolens.pt --snr 0
```

`--decode` 决定哪一档当"主结果"写进指标卡，另一档自动算出来放进对比表；`--snr` 在 demo 里是扫描列表，在 eval 里只取第一档；`--noise-aug` 和 `--noise-aug-random` 给了档位就会多训一个干净基线，代价是训练时间变成三四倍（`--noise-aug-copies` 只对随机档有意义，默认 3）。

## 用自己的数据

manifest 是每行一个 JSON：

```json
{"audio": "audio/kato-0001.wav", "text": "k a t o", "words": ["kato"], "speaker": "s1"}
```

`words` 和 `speaker` 都是可选的。有 `words` 就能算词错误率；没有就退回 `text` 里的 `|` 分隔；连分隔符也没有，整句按一个词算——宁可给一个粗的 WER，也不假装知道词边界。相对路径按 manifest 所在目录解析：

```bash
echolens train --manifest mydata/train.jsonl --dev mydata/dev.jsonl --root mydata --epochs 20
echolens eval  --manifest mydata/dev.jsonl --checkpoint out/echolens.pt
```

`examples/train_on_your_manifest.py` 是一份直接调 Python API 的版本，注释里标了每一步在干什么。

注意：模型的输出词表就是那 10 个音素 + blank。拿英文单词或中文拼音去训练它只会得到垃圾结果，想换词表得连 `PHONES` 和 `TOKENS` 一起改。

## 边界

说清楚它不是什么：

- **还是合成语音，没有真实录音。** 共振峰是稳态的设计值，没有协同发音、没有过渡段、没有韵律；"说话人"是四个数字（基频、声道长度、语速、声门倾斜），不是真人声纹。PER 0.018 不代表任何真实场景的识别能力，别拿它和 LibriSpeech 上的结果比。
- **共振峰模型是粗的。** 三级级联、带宽固定、声源是简单脉冲串；真实语音还有鼻化、气声、声道长度的时间变化。
- **语言模型只是音素 bigram。** 词表 16 个词，它压不住词级错误；没有词级 n-gram、没有前缀树、没有用外部语料训练的 LM。
- **抗噪是可选项，不是默认。** `--noise-aug`（固定档）和 `--noise-aug-random`（区间随机）都能把噪声曲线压下来，代价是陌生音色略差、训练时间三四倍；噪声类型也只有白噪，没有 babble、音乐、混响。
- **词表 10 个音素、16 个词。** 玩具规模，用来把流水线跑通、把泛化与鲁棒性可视化做对，不是为了刷指标。
- 没做流式/增量推理、量化、ONNX 导出。

如果拿它当"语音识别"的基线去对标 wav2vec / Whisper，那是不成立的；拿它当"一条命令能跑完、每一步中间结果都能看到、PER 与 WER 与泛化差距与噪声曲线都对得上"的 CTC 教学/评测框架，它是完整的。
